# wg-wss — واير‑غارد عبر WebSocket المشفّر على المنفذ 443

نفق يُغلّف حزم **WireGuard** (التي هي UDP) داخل **WebSocket فوق TLS** على المنفذ
**443**، فتبدو للشبكة كأنها زيارة عادية لموقع HTTPS. مفيد على الشبكات التي تحجب
UDP أو تسمح بمنفذ 443 فقط (فنادق، شبكات شركات، مزوّدات تحجب بروتوكول WireGuard).

مكتوب بلغة **Python 3.8+ من المكتبة القياسية فقط** — لا `pip install`، ولا أي
اعتماديات خارجية. بروتوكول WebSocket (RFC 6455) منفَّذ داخل المشروع.

---

## كيف يعمل

```
جهازك                                          الخادم (VPS)
┌──────────────────────────┐                   ┌──────────────────────────┐
│ WireGuard                │                   │  wgws server  (443/TCP)  │
│   Endpoint=127.0.0.1:51820│                  │      TLS + WebSocket     │
│        │ UDP             │                   │           │ UDP         │
│        ▼                 │                   │           ▼             │
│ wgws client ────────── TLS/WebSocket 443 ───► │  WireGuard 127.0.0.1:51820│
└──────────────────────────┘                   └──────────────────────────┘
```

- عميل `wgws` يستمع على منفذ UDP محلي، ويوجّه كل حزمة كإطار WebSocket ثنائي.
- خادم `wgws` ينهي TLS على 443، ويسلّم الحزم إلى WireGuard المحلي عبر UDP.
- لكل اتصال WebSocket مقبس UDP مستقل على الخادم، فترجع ردود WireGuard لصاحبها.
- التعمية تبقى تعمية WireGuard نفسها؛ الـTLS مجرد غلاف للتمويه والعبور.
- أي طلب لا يحمل المسار السري والرمز الصحيح يتلقّى **صفحة ويب عادية**، فلا يكشف
  الماسحات الضوئية وجود النفق.

## التشغيل على الخادم (سكربت واحد)

على VPS بنظام Debian/Ubuntu، مع اسم نطاق يشير إلى الخادم:

```bash
git clone <هذا-المستودع> && cd ew/wg-wss
sudo ./scripts/install-server.sh vpn.example.com
```

السكربت يثبّت WireGuard، ينشئ المفاتيح، يفعّل التمرير وNAT، يمنع منفذ WireGuard
من الإنترنت (يُسمح به محليًا فقط)، يجلب شهادة Let's Encrypt عبر certbot، ثم يشغّل
خدمة `wg-wss` عبر systemd. في النهاية يطبع الـ **endpoint** و**الرمز السري**.

بدون اسم نطاق (شهادة موقّعة ذاتيًا — للتجربة فقط):

```bash
sudo ./scripts/install-server.sh
```

### إضافة جهاز

```bash
sudo ./scripts/add-peer.sh phone vpn.example.com
```

يطبع ملف إعداد العميل ورمز QR (إن توفّر `qrencode`)، ويضيف الند إلى `wg0` فورًا.

## التشغيل على جهازك

```bash
# 1) شغّل الجسر (يبقى يعمل)
python3 -m wgws client wss://vpn.example.com/ws --token <الرمز>

# 2) ثم ارفع واير‑غارد بملف الإعداد الذي طبعه add-peer.sh
sudo wg-quick up phone
```

ملف إعداد العميل يشير إلى الجسر المحلي لا إلى الخادم:

```ini
[Interface]
PrivateKey = ...
Address    = 10.8.0.2/24
DNS        = 1.1.1.1
MTU        = 1280

[Peer]
PublicKey  = ...
Endpoint   = 127.0.0.1:51820     # الجسر المحلي
AllowedIPs = 0.0.0.0/0, ::/0
PersistentKeepalive = 25
```

> **مهم:** مع `AllowedIPs = 0.0.0.0/0` يجب استثناء عنوان الخادم من النفق، وإلا دار
> اتصال WebSocket داخل نفسه. أضف مسارًا مباشرًا قبل رفع الواجهة:
> `sudo ip route add <SERVER_IP>/32 via <البوابة الافتراضية>`

على الهاتف: تطبيق WireGuard الرسمي لا يشغّل جسرًا محليًا، لذا يلزم تشغيل العميل
على راوتر أو جهاز في الشبكة نفسها وتوجيه `Endpoint` إليه، أو استخدام تطبيق يدعم
WebSocket أصلًا. على ويندوز/ماك/لينكس يعمل الأمر أعلاه كما هو.

## مشاركة المنفذ 443 مع موقع حقيقي

إن كان لديك موقع على 443، ضع `wgws` خلف nginx:

```bash
python3 -m wgws server --listen 127.0.0.1:8443 --no-tls --path /ws --token <الرمز>
```

وانسخ `nginx/wg-wss.conf` بعد تعديل اسم النطاق ومسارات الشهادة. الموقع يعمل
طبيعيًا، والمسار السري وحده يذهب إلى النفق.

---

## الخيارات

| خيار | الخادم | العميل | الوصف |
|---|:--:|:--:|---|
| `--listen` | ✅ | ✅ | عنوان الاستماع (خادم: `0.0.0.0:443`، عميل: UDP محلي) |
| `--path` | ✅ | ✅ | المسار السري (افتراضي `/ws`) |
| `--token` | ✅ | ✅ | رمز مشترك يُرسل في ترويسة `Authorization` |
| `--cert` / `--key` | ✅ | — | شهادة TLS ومفتاحها |
| `--no-tls` | ✅ | — | HTTP عادي خلف بروكسي عكسي فقط |
| `--decoy-file` | ✅ | — | صفحة HTML تُقدَّم لغير المصرّح لهم |
| `--wg` | ✅ | — | عنوان WireGuard المحلي (افتراضي `127.0.0.1:51820`) |
| `--insecure` | — | ✅ | تعطيل التحقق من الشهادة (شهادة ذاتية فقط) |
| `--ca` | — | ✅ | ملف CA للتحقق من شهادة ذاتية |
| `--sni` / `--host-header` | — | ✅ | تخصيص اسم TLS وترويسة Host |
| `--ping-interval` | ✅ | ✅ | فاصل نبضات البقاء بالثواني (افتراضي 25) |
| `--idle-timeout` | ✅ | ✅ | إغلاق النفق الخامل بعد هذه المدة |

كل الخيارات تقبل متغيرات بيئة بالصيغة `WGWS_PATH`، `WGWS_TOKEN`، `WGWS_CERT` …

## الاختبارات

```bash
python3 -m unittest discover -s tests -v   # اختبارات وحدة لطبقة WebSocket
python3 tests/e2e.py                       # مسار البيانات كاملًا عبر TLS حقيقي
```

الاختبار الثالث يشغّل جهازي WireGuard حقيقيين في فضاء المستخدم (مكتبة
wireguard-go) ويمرّر طلب HTTP داخل النفق — يثبت أن المصافحة وحركة IP تعملان فعليًا
فوق WebSocket. يحتاج Go واتصالًا بالإنترنت لتنزيل المكتبة (لا يحتاج صلاحية root).

## ملاحظات عملية

- **MTU:** استخدم `MTU = 1280` في إعداد العميل. WireGuard فوق TCP/TLS يضيف
  ترويسات، والقيمة الافتراضية 1420 تسبب تجزئة وبطئًا.
- **TCP فوق TCP:** أي نفق فوق TCP يعاني من «انهيار النافذة» عند فقد الحزم؛
  التوقّع الطبيعي هو أداء أقل من WireGuard المباشر على UDP. استخدم هذا الحل عند
  حجب UDP فقط.
- **الأمان:** التعمية الحقيقية من WireGuard. الرمز السري والمسار السري يمنعان
  الاكتشاف السلبي، وليسا بديلًا عن مفاتيح WireGuard.
- **التنصّت النشط:** الغلاف يشبه HTTPS عاديًا، لكنه ليس مُصمَّمًا لمقاومة تحليل
  توقيت أو حجم الحزم من خصم متقدّم.
- **القانون:** استعمله على خادم تملكه ووفق الأنظمة المعمول بها في بلدك.

## استكشاف الأعطال

| العرض | الفحص |
|---|---|
| العميل يعيد المحاولة باستمرار | صحة الرمز والمسار؛ هل 443 مفتوح؟ `curl -v https://HOST/` يجب أن يعرض صفحة |
| النفق يفتح ولا يمر شيء | هل WireGuard يعمل؟ `wg show`؛ هل `--wg` يطابق `ListenPort`؟ |
| المصافحة تنجح والإنترنت لا يعمل | `net.ipv4.ip_forward=1` وقواعد MASQUERADE، وتحقق من DNS |
| بطء أو تقطّع | اضبط `MTU = 1280`، وتأكد أن عنوان الخادم مستثنى من `AllowedIPs` |
| `certificate verify failed` | استخدم `--ca cert.pem` أو `--insecure` مع الشهادة الذاتية |

سجلات الخادم: `journalctl -u wg-wss -f`
